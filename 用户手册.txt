1  软件概述
================================================================================

--------------------------------------------------------------------------------
1.1 软件名称与版本
--------------------------------------------------------------------------------
软件名称：ESP32-P4 多人游戏掌机平台（工程代号 The-Defect）
软件版本：v1.0
所属作品：ESP32-P4 多人游戏掌机
软件形态：固化在设备主控中的嵌入式固件（非 App / 非桌面软件），通过 6 寸
          触控屏 + 自研 BLE 手柄与用户交互，同时提供 HTTP/WebSocket 服务
          供浏览器远程投屏、触控与手柄输入。
组成模块：系统固件 + 手柄固件 + 市场服务端
          （系统固件 main/ + 手柄固件 esp32c6HidJoystick 子模块 +
           市场服务端 The-Defect-Market 子模块）

【软件在嵌入式系统中的作用】
本软件是整台掌机的核心，运行于 ESP32-P4 主控，统筹协调以下职责：
  - 设备控制：初始化并驱动 MIPI DSI 显示屏（ILI9881C）、电容触摸（GT911）、
    音频编解码器（ES8311）、电池 ADC、背光 PWM 等全部外设；
  - 数据采集：采集手柄输入（BLE / Web / UDP / 本地）、触摸输入、电池电压、
    CPU 利用率、WiFi 信号与 mDNS 设备信息；
  - 算法处理：游戏逻辑（俄罗斯方块 7-bag/SRS、水果忍者、贪吃蛇、中国象棋
    AI 引擎）、屏幕 MJPEG 硬件编码、PPA 2D 硬件加速渲染、FreeType 字体栅格化、
    输入法词库检索；
  - 通信交互：自研 HTTP/WebSocket/UDP 网络栈（端口 80 / 8080 / 8082）、mDNS
    服务发现、BLE 手柄连接、P4-P4 跨主机联机、AI 助手 OpenAI 兼容 API 交互；
  - 结果展示：通过 LVGL 9.4 在 6 寸 720x1280 屏幕上呈现桌面、游戏、系统设置、
    AI 对话、游戏市场等全部 UI，并支持浏览器远程投屏串流。

--------------------------------------------------------------------------------
1.2 应用场景与设计目标
--------------------------------------------------------------------------------
【应用场景】
  - 客厅 / 宿舍 / 教室等局域网的多人派对娱乐；
  - 多台主机跨局域网互联的团体对战；
  - 使用自然语言操控设备的智能娱乐终端（AI 助手）；
  - 社区 Lua 小游戏的下载、创作与分享（游戏市场 + AI 生成）。

【设计目标】
  - 即开即玩、零配置：开机自动连接上次保存的 WiFi，失败自动切换 AP 热点，
    无需路由器、无需下载 App；
  - 全链路自研：ESP32-P4 + ESP32-C6 双芯架构，LVGL 9.4 GUI、自研 HTTP/WS/UDP
    网络栈、自研 BLE HID 手柄、ES8311 音频、硬件 JPEG 串流；
  - 多人同屏 + 跨主机联机：最多 4 只 BLE 手柄，1 台主机 + 最多 3 台从机互联；
  - AI 增强：集成 OpenAI 兼容 API，AI 可执行系统操作、跨界面导航，并能动态
    生成 Lua 游戏；
  - 性能优先：PPA 2D 硬件加速渲染、MJPEG 硬件编码零拷贝串流，稳定 60fps。

2  运行环境
================================================================================

--------------------------------------------------------------------------------
2.1 硬件环境
--------------------------------------------------------------------------------
【主控芯片】
  - ESP32-P4（主控 SoC）：双核 HP 处理器 + LP Core，集成 PPA（Pixel
    Processing Accelerator）2D 硬件加速、硬件 JPEG 编码器、MIPI DSI 显示
    接口、PSRAM 接口，负责全部渲染、游戏逻辑与系统调度。
  - ESP32-C6（协处理器）：经 SDIO（esp_hosted）挂载于主控，独立承担 WiFi
    STA/AP 双模与 BLE 蓝牙射频，与主控分工协作、互不抢占。

【开发板】
  - 自研 PCB 整机：一体化掌机形态，集成主控 + 协处理器 + 电源管理 + 电池
    充电 + 音频功放 + 屏幕排线 + USB 转串口（烧录 / 日志调试接口）。

【显示 / 输出（执行机构）】
  - 显示屏：ILI9881C 6 寸 720 x 1280，MIPI DSI 接口，背光 PWM 可调（亮度
    可软件调节并持久化）。
  - 音频：ES8311 编解码器（I2C 控制 + I2S 数据，MCLK=13 / BCK=12 / WS=10 /
    DOUT=9）+ 功放（使能 GPIO53）+ 扬声器，支持多流混音播放。

【传感器】
  - 触摸屏：GT911 5 点电容触摸，I2C 接口（地址 0x5D / 0x14），INT/RST 接
    GPIO46 / GPIO47。
  - 电池电压检测：ADC1_CH6 分压采样（5.1k + 10.2k）。
  - 充电检测：GPIO23 电平（低电平 = 充电中）。

【通信模块】
  - WiFi：由 ESP32-C6 实现，STA / AP 双模 + NAT 转发。
  - 蓝牙 BLE：由 ESP32-C6 实现（NimBLE），连接自研无线手柄。
  - 有线串口：USB 转串口，用于烧录与日志监控。
  - 网络服务：设备自建 HTTP（80）/ WebSocket（8080）/ UDP（8082）服务与
    mDNS 设备发现（esp32p4.local）。

【输入设备（外设）】
  - 无线手柄：自研 ESP32-C6 BLE HID 手柄（固件 esp32c6HidJoystick），最多
    4 只同时连接，含摇杆、按键、扳机、十字键与电池电量。

【电源模块】
  - 锂电池供电（带充电管理），电量实时估算，支持 Deep-sleep 低功耗关机。

【存储】
  - 板载 SPI Flash：6MB 应用固件区 + 16MB FAT 数据分区（挂载 /root/）。
  - PSRAM：作为系统主堆与显示帧缓冲（CONFIG_SPIRAM_USE_MALLOC=y）。
  - Micro SD 卡（可选）：挂载 /root/sd。

--------------------------------------------------------------------------------
2.2 软件环境
--------------------------------------------------------------------------------
【操作系统 / RTOS】
  - FreeRTOS（ESP-IDF 内嵌）：双核实时调度。
  - 自研 Task 协程调度器：轮询式轻量协程，支持优先级 / CPU 亲和性管理。
  - Mutex RAII 锁：多线程互斥保护。

【SDK / 开发框架】
  - ESP-IDF 5.x（esp32p4 / esp32c6 目标）：乐鑫官方固件开发框架。
  - 开发语言：C++20（固件）/ C（部分底层）/ Lua 5.5（脚本引擎）。

【GUI / 渲染】
  - LVGL 9.4 + esp_lvgl_adapter：GUI 框架（PPA 硬件加速，
    CONFIG_LV_DRAW_SW_DRAW_UNIT_CNT = 1）。
  - esp_lv_decoder / esp_lv_fs：图片解码与文件系统适配。

【驱动库】
  - esp_lcd_ili9881c：MIPI DSI 面板驱动。
  - esp_lcd_touch_gt911：电容触摸驱动。
  - ES8311 驱动：音频编解码器（I2C + I2S）。
  - esp_hosted：P4-C6 SDIO 协处理器驱动。
  - NimBLE：BLE 协议栈（P4 host + C6 controller）。
  - GPIO / I2C / ADC 驱动封装（main/gpio、main/iic 等）。

【运行时】
  - Lua 5.5 脚本引擎（安全沙箱，仅开放安全标准库）。
  - 自研 HTTP / WebSocket / UDP 网络栈（裸 socket，无第三方依赖）。
  - esp_audio_render 多流混音运行时。

【算法库】
  - FreeType + NotoSC.ttf：字体栅格化渲染（24 / 32 / 56 三档字号）。
  - 硬件 JPEG 编码器（esp_new_jpeg）：屏幕串流 MJPEG 零拷贝编码。
  - PPA（Pixel Processing Accelerator）：2D fill / blend / SRM 硬件加速。
  - 中国象棋 AI 引擎：内置走子搜索算法。
  - cJSON：AI 响应与配置 JSON 解析。
  - 输入法词库检索：拼音 / 五笔 / 混合词库（Rime 提取）。

【组件补丁】
  - patches/ 目录 6 个补丁：帧回调 / PPA 队列 / SRM bypass / WS transport /
    IME iuv 过滤 / count uint16。


================================================================================
3  软件功能说明
================================================================================

--------------------------------------------------------------------------------
3.1 系统桌面与导航
--------------------------------------------------------------------------------
系统以"桌面启动器 + 多栈导航"为核心。开机后进入桌面，显示 7 张游戏/应用
卡片（俄罗斯方块、水果忍者、贪吃蛇、中国象棋、Lua 脚本管理、游戏市场、
AI 助手等），状态栏显示电量、网络、主机名等状态。

  - 导航架构：AppStackManager 多栈导航（根栈 = 桌面 + 游戏独立栈），支持
    入栈 / 出栈 / 替换，异步删除 + 操作去重，防止快速连点重复进入。
  - 桌面焦点组：3 个焦点组（卡片 / 底部按钮 / 状态栏），支持手柄 4 向导航。
  - 输入方式：触摸屏点击 + 蓝牙手柄按键（双通道等效）。
  - AI 入口：桌面 AI 卡片 / 顶部下滑 / 手柄组合键（Y + X + B）唤起 AI 助手。

--------------------------------------------------------------------------------
3.2 游戏功能
--------------------------------------------------------------------------------
内置 4 款本地游戏 + Lua 脚本游戏 + 市场下载游戏：

  1) 俄罗斯方块（3 人对战）
     - Host-authoritative 架构，共享 7-bag 队列、SRS 旋转规则；
     - 内置 3 玩家槽位（本机 P0 + 2 个 WebSocket 远程）；
     - 支持跨主机远程游玩：主机通过 TCP 连接从机（端口 8084），20fps 异步
       snapshot 下发，从机全屏 / 动态分屏渲染远程主机画面。

  2) 水果忍者（2 人对战）
     - 多人同屏切水果，含房间系统（FruitNinjaRoom）自动配对。

  3) 贪吃蛇（4 人对战）
     - 经典蛇对战，snakeGame 逻辑 + snakeRoom 房间配对。

  4) 中国象棋（双人 + AI）
     - 本地双人对战 + 内置 AI 引擎（chessAI.cpp），单人也能玩。

  5) Lua 脚本游戏（LuaGameApp）
     - 60fps 循环调用 Lua loop(dt)；
     - 提供 display / input / audio / thread / storage 5 个绑定模块；
     - 安全沙箱：禁用 io/os/package/debug，防死循环（指令计数 hook 中断），
       存档限定 /root/lua/data/。

  6) 游戏市场（MarketApp）
     - 浏览社区 Lua 游戏（截图网格懒加载 + 详情 + 下载运行 / 本地运行）；
     - 已下载脚本离线可玩，卡片显示"已装"角标，下载量自动上报。

--------------------------------------------------------------------------------
3.3 手柄管理与连接
--------------------------------------------------------------------------------
系统内置 BLE 手柄管理器（BleGamepad）与统一输入抽象层（VirtualGamepad）：

  - 最多 4 只手柄同时连接，输入以固定 60fps 全量分发到前台 App；
  - NVS 持久化配对：手柄开机后自动重连已配对设备（约 5 秒）；
  - 手柄电量：通过 BLE Battery Service 读取并显示；
  - 输入来源统一：本机 BLE + Web 客户端（/ws/input）+ P4-P4 UDP（端口 8082）
    + 本地输入，经 hostMask 掩码过滤后分发；
  - 掩码路由：主机通过 ConsoleManager 控制各 (host, player) 输入是否进入本地
    游戏，同一输入不会被本地与远程同时消费；
  - 界面入口：桌面 → 设置 → 蓝牙手柄（扫描 / 配对 / 断开 / 删除配对）。

--------------------------------------------------------------------------------
3.4 HID 模式（PC 连接）
--------------------------------------------------------------------------------
本项目手柄为自研 ESP32-C6 BLE HID 手柄（固件 esp32c6HidJoystick），本身即
标准 BLE HID（Human Interface Device）设备，除连接本机主机外，还可作为
标准蓝牙手柄直接配对连接 PC / 笔记本 / 手机等支持 BLE HID 的设备：

  - 兼容系统：Windows / Linux / Android / Steam 等标准蓝牙手柄识别；
  - 免驱动：以标准 HID 游戏手柄协议上报按键、摇杆、扳机、十字键；
  - 双用途：同一只手柄既可用于本机游戏，也可切换到 PC 使用；
  - 按钮定义：与 C6 手柄固件 HID 报告描述符对齐（见 gamepadState.hpp）。

【说明】手柄固件源码位于 gamepad/ 子模块（独立仓库），连接 PC 的具体配对
方式见第 5.4 节操作流程。

--------------------------------------------------------------------------------
3.5 网络服务（屏幕串流 / Web 触控）
--------------------------------------------------------------------------------
设备开机后自动启动以下网络服务：

  1) HTTP 服务器（端口 80）
     - 提供内置网页：屏幕串流查看器、Tetris 网页客户端、虚拟手柄、
       WiFi 网页配置等。

  2) WebSocket 服务器（端口 8080）
     - /ws/touch   ：Web 触摸注入（远程触控操作屏幕）；
     - /ws/stream  ：屏幕 MJPEG 串流（硬件 JPEG 编码，零拷贝）；
     - /ws/input   ：Web 手柄输入（11 字节二进制帧）；
     - /ws/console ：设备管理通道（注册 / 心跳 / slots_update 广播）。

  3) UDP 输入（端口 8082）
     - P4 - P4 低延迟手柄输入转发（持久 socket，60fps）。

  4) mDNS 服务发现
     - 默认主机名 esp32p4，浏览器访问 esp32p4.local；
     - 注册 _http / _ws / _p4console 服务，支持局域网设备发现。

  5) 屏幕串流（ScreenStream）
     - 直接读取 bridge 帧缓冲 + 硬件 JPEG 编码，零额外渲染、零额外拷贝；
     - 配合 /ws/stream 实现浏览器实时投屏，配合 /ws/touch 实现远程触控。

--------------------------------------------------------------------------------
3.6 电源与音量管理
--------------------------------------------------------------------------------
  - 电源管理（PowerManagementApp）：
      主机 + 手柄电量显示、关机（Deep-sleep）、低功耗。
  - 电池检测（BatteryManager）：
      ADC 电量估算（0 ~ 100%）、充电检测（GPIO23 低电平 = 充电中）、
      充电动画与状态图标（绿 / 黄 / 红三色分级）。
  - 音量管理（Audio + ES8311）：
      多流混音播放（MP3 / AAC / FLAC / WAV），主音量硬件级调节并 NVS
      持久化，DAC 随流自动上电 / 断电省电。
  - 背光亮度：桌面快捷调节，亮度 NVS 持久化，重启自动恢复。


================================================================================
4  安装配置与运行准备
================================================================================

--------------------------------------------------------------------------------
4.1 开发环境搭建
--------------------------------------------------------------------------------
1. 安装 ESP-IDF 5.x（须含 esp32p4 与 esp32c6 目标支持）；
2. 安装 Visual Studio Code + ESP-IDF 扩展（编译 / 烧录 / 监控一体化）；
3. 克隆项目并拉取子模块：
     git clone --recurse-submodules <仓库地址>
   或已克隆后补拉：
     git submodule update --init --recursive
   （子模块：gamepad/ 手柄固件、The-Defect-Market/ 市场服务端）
4. 对 managed_components 应用补丁：
     bash patches/apply.sh
   （注意：执行 idf.py reconfigure 后需重新打补丁）

--------------------------------------------------------------------------------
4.2 固件编译与烧录
--------------------------------------------------------------------------------
在项目根目录执行（或使用 ESP-IDF 扩展图形化操作）：

    idf.py build                 # 编译固件
    idf.py -p <串口> flash       # 烧录（Windows 下如 COM3 / COM7）
    idf.py -p <串口> monitor     # 打开串口监控查看日志

烧录完成后，还需将 reserces/ 目录资源上传到 FAT 分区（挂载 /root/）：

    reserces/
    ├── server/       # HTTP 网页资源（投屏查看器、Tetris、虚拟手柄、WiFi 配置）
    ├── lua/          # Lua 测试 / 示例脚本
    └── system/       # 系统文件（必传）
        ├── NotoSC.ttf           # 全局默认字体（缺失则无中文字体）
        ├── pinyin_dict.txt      # 拼音词库
        ├── wubi_dict.txt        # 五笔词库
        └── wubi_pinyin_dict.txt # 五笔 + 拼音混合词库

--------------------------------------------------------------------------------
4.3 手柄配对与连接
--------------------------------------------------------------------------------
1. 确保设备已开机并进入桌面；
2. 进入 设置 → 蓝牙手柄（BleSettingsApp）；
3. 打开手柄电源，点击"扫描"；
4. 在扫描列表中选择本机手柄名称 → 确认配对；
5. 配对成功后手柄信息写入 NVS，之后开机自动重连；
6. 最多可配对 / 连接 4 只手柄（玩家编号 P0 ~ P3）。


================================================================================
5  操作流程
================================================================================

--------------------------------------------------------------------------------
5.1 开机与主界面
--------------------------------------------------------------------------------
1. 接通电源（或长按电源键）开机；
2. 系统自动初始化：挂载存储 → 初始化显示 → 启动网络服务 → 进入桌面
   （约数秒，无需任何人工操作）；
3. 桌面显示 7 张游戏 / 应用卡片 + 顶部状态栏（电量 / 网络 / 主机名）；
4. 触摸点击卡片或使用手柄 ← / → 切换、A 键确认进入应用；
5. 若开机 WiFi 连接失败，系统自动切换为 AP 热点（SSID: esp32p4，
   密码: 12345678），手机 / 电脑连接后可继续使用网页功能。

--------------------------------------------------------------------------------
5.2 游戏启动与操作
--------------------------------------------------------------------------------
1. 在桌面选择游戏卡片，按 A 键 / 触摸进入；
2. 游戏房间界面选择玩家人数与模式（如俄罗斯方块选人数、象棋选双人 / AI）；
3. 手柄操作规则：
      方向键 / 摇杆：移动 / 旋转 / 导航
      A 键          ：确认 / 操作
      B 键          ：返回上一级
4. 游戏结束显示比分 / 排名，按 B 键返回桌面；
5. 手柄输入由 VirtualGamepad 60fps 分发，操作无感延迟。

--------------------------------------------------------------------------------
5.3 多人联机流程
--------------------------------------------------------------------------------
【同屏多人（单机多手柄）】
1. 配对 2 ~ 4 只手柄（见 4.3）；
2. 进入支持多人的游戏（俄罗斯方块 3 人、水果忍者 2 人、贪吃蛇 4 人、
   象棋 2 人）；
3. 房间内为每个玩家分配手柄（P0 ~ P3），即可同屏对战。

【跨主机联机（多台主机互联）】
1. 主机与从机均开机，并处于同一局域网（或主机的 AP 热点下）；
2. 从机进入 桌面 → 多主机管理（状态栏图标）；
3. 从机点击"扫描"，mDNS 发现主机后点击连接，成为从机并分配槽位
   （Slot 1 ~ 3）；
4. 主机在 ConsoleManager 中通过 P0 ~ P3 掩码按钮，决定各从机哪些手柄输入
   进入本地游戏；
5. 从机可进入"Tetris 远程游戏"，全屏 / 分屏渲染主机画面，手柄输入经
   UDP（端口 8082）自动转发到主机，无需手动配置。

--------------------------------------------------------------------------------
5.4 HID 连接 PC 流程
--------------------------------------------------------------------------------
将手柄作为标准蓝牙手柄连接 PC：

1. 手柄进入配对模式（按手柄配对键，参考手柄固件 readme）；
2. PC 端打开 蓝牙设置 → 添加设备 → 蓝牙；
3. 在列表中选择本机手柄名称 → 配对连接；
4. 连接成功后，Windows / Steam 等自动识别为标准游戏手柄；
5. 在游戏中检测 / 映射按键后即可使用；
6. 如需回到本机主机使用：断开 PC 连接，主机端重新配对 / 开机自动重连。

【说明】手柄与主机的按钮协议以 gamepadState.hpp 为准，与 HID 报告描述符
对齐；具体配对键位以 gamepad/ 子模块固件文档为准。

--------------------------------------------------------------------------------
5.5 屏幕串流查看流程
--------------------------------------------------------------------------------
1. 手机 / 电脑连接设备所在网络（设备开机自动连 WiFi，或连设备 AP 热点）；
2. 浏览器访问：http://esp32p4.local（或设备 IP）；
3. 打开"屏幕串流"页面，实时查看设备画面（MJPEG 硬件编码）；
4. 打开"虚拟手柄"页面，可通过 Web 发送手柄输入（测试 /ws/input）；
5. 网页触摸操作经 /ws/touch 远程注入，与本地触摸等效。

--------------------------------------------------------------------------------
5.6 关机与充电
--------------------------------------------------------------------------------
1. 进入 设置 → 电源管理；
2. 查看主机与各手柄电量；
3. 点击"关机"进入 Deep-sleep 低功耗模式（再次开机恢复）；
4. 充电：插入充电器，状态栏显示充电动画；充电中 GPIO23 为低电平，
   充满后停止。

================================================================================
7  常见问题与处理
================================================================================

问题 1：触摸无反应
  可能原因：GT911 未检测到（排线 / 供电），I2C 地址异常。
  处理    ：查看串口是否打印 "Touch controller found"；检查触摸排线与
            I2C 地址 0x5D / 0x14；若打印 "Touch controller not found" 则
            检查硬件连接。

问题 2：屏幕不亮 / 花屏
  可能原因：屏排线未接好；组件补丁未打；idf.py reconfigure 后补丁失效。
  处理    ：重新打补丁 bash patches/apply.sh；检查 MIPI DSI 排线；查看串口
            FPS 日志确认 LVGL 是否正常运行。

问题 3：中文字体不显示
  可能原因：/root/system/NotoSC.ttf 未上传。
  处理    ：上传字体到 FAT 分区；串口会打印 "缺失字体/root/system/NotoSC.ttf"
            告警，此时系统已回退 LVGL 内置字体。

问题 4：WiFi 连接失败
  可能原因：密码错误 / 信号弱 / 上次配置失效。
  处理    ：设备端 WiFi 设置重新扫描连接；或连接 AP 热点 esp32p4
            （密码 12345678）后用网页配置。

问题 5：浏览器无法访问 esp32p4.local
  可能原因：设备未连网 / 主机名被修改 / mDNS 未生效。
  处理    ：改用设备 IP 访问；确认手机 / 电脑与设备同网段；通过
            GET/POST /api/mdnsConfig 查看 / 修改主机名。

问题 6：手柄无法连接
  可能原因：已超过 4 只上限；配对信息丢失；BLE 未初始化成功。
  处理    ：进入蓝牙手柄设置重新扫描配对；确认连接数 <= 4；检查 C6
            协处理器 SDIO 是否就绪（Slave::waitReady）。

问题 7：手柄已连接但输入无反应
  可能原因：输入被 hostMask 掩码过滤；AI 助手浮动窗处于打开状态（独占输入）。
  处理    ：检查"多主机管理"中 P0~P3 掩码是否开启；关闭 AI 助手浮动窗。

问题 8：跨主机联机失败
  可能原因：不在同一局域网 / mDNS 发现不到 / 端口被占用。
  处理    ：确认主机与从机同网段；重新扫描；检查 8080 / 8082 端口是否被占。

问题 9：屏幕串流卡顿 / 黑屏
  可能原因：网络带宽不足；串流服务未启动。
  处理    ：检查网络质量；确认 /ws/stream 已注册、ScreenStream 已启动。

问题 10：没有声音
  可能原因：ES8311 初始化失败；音量为 0；音频格式不支持。
  处理    ：查看串口是否打印 "音频管理器初始化失败"；调高主音量；确认文件
            为 MP3 / AAC / FLAC / WAV 格式。

问题 11：编译报错"重复定义"
  可能原因：对已应用的补丁重复执行了全量 apply.sh。
  处理    ：不要对已打补丁的组件重跑全量脚本；新补丁单独执行
            patch -d <组件目录> -p1 < xxx.patch；或先 apply.sh --revert
            还原后统一重打。

问题 12：渲染花屏 / 黑线
  可能原因：CONFIG_LV_DRAW_SW_DRAW_UNIT_CNT 大于 1；PPA fill/blend 队列溢出。
  处理    ：确认 CONFIG_LV_DRAW_SW_DRAW_UNIT_CNT=1；应用 PPA max_pending
            补丁（0002）。

问题 13：Lua 游戏死循环 / 卡死
  可能原因：脚本死循环。
  处理    ：指令计数 hook 会自动中断（1000 万条 / 帧上限）并报错；可在
            Lua 脚本管理器中删除对应脚本。

问题 14：Lua 游戏报错
  可能原因：脚本运行时错误。
  处理    ：错误会自动回传 AI，下次对话可让 AI 修复重新生成；也可在
            LuaManagerApp 中查看 / 编辑脚本。

问题 15：下载市场游戏失败
  可能原因：网络不通；market_config.json 服务器地址错误。
  处理    ：检查网络连接；检查 /root/system/market_config.json 的
            server_url 字段。

问题 16：电池电量显示不准
  可能原因：ADC 采样偏差。
  处理    ：校准分压参数（5.1k + 10.2k）；以电压值为参考。

问题 17：开机反复重启
  可能原因：Flash 分区异常；资源未上传导致初始化失败。
  处理    ：重新烧录固件 + 上传 reserces/ 资源；必要时格式化 FAT 分区。
